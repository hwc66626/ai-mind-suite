# Inner Voice MCP —— 内心声音：AI 给自己设的闹钟、便签与质问

第三款 MCP。核心命题：**质问是 AI 自己设置的**，但要有一个独立于会话的"生物钟"
替未来的自己去叩门——就像现实中的闹钟和便签："睡觉前要给手机充电"。

## 为什么不一样

| 你要的 | 实现 | 科学依据 |
|---|---|---|
| 独立进程来质问自己 | 守护进程 `daemon.py`：独立会话组常驻，服务器只负责懒拉起；**所有 AI 会话关掉，闹钟仍在走**，下次开机收件箱还在 | 前瞻记忆（prospective memory）不需要"在场" |
| 闹钟式提醒 | 时间前瞻记忆：`"23:00"` 每日 / `"+90m"` 相对 / ISO 绝对；错过的补一声不丢失；循环自动排下一次 | Einstein & McDaniel 时间性前瞻记忆 |
| 便签式提醒 | 事件前瞻记忆：关键词命中当前上下文即冒出（"改验签前先查生产密钥"），带冷却防刷屏，近重复便签自动去重 | 执行意图 if-then 计划（Gollwitzer 1999）：if-then 使目标达成率翻倍 |
| 质问是 AI 自己设置的 | `ask_myself`：AI 写给未来自己的问题，挂在闸门上（任务开始/回答前/提交前/删除前/结束）；内置检查单可一键 `preset_checklist` | 自我提问学习法（King 1992）、元认知监控（Flavell 1979） |
| 不回答会怎样 | 蔡格尼克式升级：未答叩门 30 分钟后优先级+1 持续萦绕，封顶 4 级后进复盘"悬而未决" | 蔡格尼克效应：未完成任务持续侵入意识 |
| 提醒自己别忘事 ≠ 记住事 | 回答叩门默认回写 brain-memory 长期记忆（"自问…自答…"），内省经验沉淀为情景记忆 | 记忆重构理论：复述即巩固 |
| 复盘 | `review`：形同虚设的质问（问3次没答过）、已内化的便签（答满5次→建议停用+固化）、一直在逃避的问题（小睡≥3次） | 习惯养成与内化 |

## 架构

```
        ┌────────────────────────┐        ┌───────────────────────────┐
        │  MCP 客户端（会话内）     │        │  守护进程（会话外，常驻）     │
        │  ask_myself / set_note  │        │  daemon.py（独立会话组）     │
        │  set_alarm / check_gate │        │  · 到点闹钟 -> pings        │
        │  inbox / answer / …     │        │  · 未答升级（萦绕）          │
        └───────────┬────────────┘        │  · 心跳写入 meta            │
                    │ 懒拉起/复用 ────────► └────────────┬──────────────┘
                    │                                   │ WAL 共享
        ┌───────────▼───────────────────────────────────▼──────────────┐
        │  voice.db（voices 永不删除；pings 队列，已答按 30 天清理）        │
        └───────────────────────────┬───────────────────────────────────┘
                                    │ 可选桥（brain-memory-mcp 在同级目录）
                    ┌───────────────▼───────────────┐
                    │  answer -> remember 回写长期记忆 │
                    │  reflect -> recall 记忆对照提问  │
                    └───────────────────────────────┘
```

单实例保证：meta 表 `daemon_lock` 存 `pid|启动时间`，CAS 抢锁；第二个实例发现
锁持有者 PID 存活即退出。心跳超过 3×间隔 或 PID 已死判为失联，可重新拉起。

## 13 个工具

| 工具 | 作用 |
|---|---|
| `ask_myself` | 给自己挂一条闸门质问（AI 自己写的问题） |
| `set_alarm` | 闹钟：`"23:00"`（每日）/ `"+90m"` / ISO；`every=0` 一次性 |
| `set_note` | 便签：关键词命中上下文即触发；近重复自动去重 |
| `preset_checklist` | 一键登记闸门内置检查单（提交前/删除前/回答前…） |
| `list_voices` / `deactivate_voice` | 查看 / 软停用（永不物理删除） |
| `check_gate` | 过闸门：此刻该问什么（质问+便签命中+闹钟叩门） |
| `inbox` | 收件箱：守护进程攒下的未答叩门，升级的置顶 |
| `answer` / `snooze` | 回答（默认回写长期记忆）/ 小睡稍后再问 |
| `reflect` | 即时自问：自设质问 + 苏格拉底模板 + 记忆对照 |
| `review` | 复盘：形同虚设 / 已内化 / 悬而未决 / 一直在逃避 |
| `daemon_status` | 守护进程心跳与存活（顺带确保已拉起） |

## 快速开始

```bash
pip install -r requirements.txt          # 只需官方 mcp SDK
python tests/test_voice.py               # 44 项断言
python demo.py                           # 离线演示（不真拉进程）
```

守护进程三种管理方式：
1. **自动**（默认）：首次调用 `inbox` / `check_gate` / `set_alarm` 时服务器自动拉起
2. **手动**：`python daemon.py start|status|stop|tick`（stop 为优雅停止：置旗，≤1 个心跳周期内退出并清锁清心跳；Windows 上进程探测走 WinAPI，绝不用 `os.kill` 探活）
3. **禁止**（CI/测试）：环境变量 `INNER_MIND_NO_DAEMON=1`

跨平台说明：Linux/macOS 用新会话组脱离父进程，Windows 用新进程组 + DETACHED；
心跳格式 `ISO时间|间隔秒`，存活判定用守护进程自报的间隔，不依赖调用方的配置。

## 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `INNER_MIND_DB` | `~/.inner_mind/voice.db` | 数据库位置 |
| `INNER_MIND_DAEMON_INTERVAL` | `30` | 守护进程心跳间隔（秒） |
| `INNER_MIND_NO_DAEMON` | 未设 | 设为 1 则服务器不自动拉起进程 |
| `BRAIN_MEMORY_DB` | `~/.brain_memory/memory.db` | 记忆桥目标库（可选联动） |

## 设计取舍

- **voices 永不删除**：与前两款一致——停用只置 `active=0`，触发统计完整保留
- **pings 是队列**：已答的按 30 天清理（与"记忆永不删除"不冲突：重要的东西
  在 answer 时已经回写长期记忆，pings 只是提醒的载体）
- **零强依赖**：核心仅标准库；brain-memory 桥是可选的（不在同级目录也能跑，
  只是失去问答回写与记忆对照）
- **时间统一本地 naive**：守护进程与服务器同机运行，无时区歧义
